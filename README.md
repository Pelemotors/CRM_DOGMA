# CRM_DOGMA — מדריך שימוש

מערכת CRM מקומית לסוכנות **Wonder מוטורס**. שם הסוכנות מוגדר ב־[`config/agency.json`](config/agency.json).

המערכת מנהלת לידים ולקוחות, מלאי רכבים (כולל קטגוריות והתאמה), בדיקת החלפה, מחשבון מימון, מעקבים ופגישות, מכירות, קופה, הפקת מסמכי PDF, ו־WhatsApp אישי לכל עובד.

כל הנתונים נשמרים במחשב השרת בתיקיית `data/` — אין ענן חובה.

---

## דרישות

- **Node.js 18+**
- **Chrome** (לחיבור WhatsApp ולהפקת PDF)
- Windows מומלץ (סקריפטי `RUN.bat` / `STOP.bat`)
- מחשב שרת אחד ברשת המשרד שמריץ את האפליקציה

---

## התקנה והפעלה

```powershell
npm install
```

1. הרץ `RUN.bat` (השאר את החלון פתוח) — או: `npm run dashboard`
2. כתובת מקומית: `http://127.0.0.1:3000`  
   אם הוגדרו תעודות HTTPS: `https://127.0.0.1:3000`
3. לעובדים ברשת: השתמש בכתובת ה־LAN שמופיעה בחלון השרת, **עם https** אחרי הגדרת תעודות  
   דוגמה: `https://192.168.x.x:3000`  
   בלי HTTPS ברשת עלולה להופיע `ERR_EMPTY_RESPONSE`

### HTTPS (פעם אחת)

1. במחשב השרת: `setup-https.bat`
2. בכל מחשב עובד: `INSTALL-TRUST.bat` (או אישור ידני בדפדפן)

### עצירה

סגור את חלון `RUN.bat` או הרץ `STOP.bat`.

### הקצאת לקוחות (חשוב)

- כשנציג **מקים לקוח חדש** — הלקוח מוקצה אליו אוטומטית.
- נציג רואה רק לקוחות שהוא **הקים** או שמנהל / מנהל מערכת **הקצה** לו.
- רק מנהל / מנהל מערכת יכולים לשנות «נציג משויך» בפרופיל הלקוח.
- לקוחות ישנים בלי הקצאה: מנהל מקצה אותם ידנית לנציג.

ייבוא מלאי/לידים מקובץ Excel — **למנהלים בלבד**. נציג יכול להוסיף ולערוך רכבים במלאי ישירות מהממשק.

## מקרי שימוש

### 1. לקוח חדש → התאמות מלאי → קישור רכב

1. **לקוחות** ← לקוח חדש (או מקיצור במסך סוכן).
2. אופציונלי: תקציב, החזר חודשי רצוי, **קטגוריות רצויות** (חשמלי / הייבריד / בנזין / דיזל / 7 מקומות).
3. המערכת מציגה עד **5 רכבים** מהמלאי שמתאימים (קטגוריה AND + דירוג לפי תקציב/החזר).
4. בחר רכב מההתאמות (או חפש במלאי) ← שמור.
5. בפרופיל הלקוח: אותן התאמות מופיעות גבוה בעמוד; «קשר ללקוח» מוסיף לכרטיס.
6. הגדר מעקב / פגישה; עדכן שרשור טיפול (כולל «אין מענה» → תזכורת 24ש׳ + טיוטת WhatsApp).

### 2. הקצאת לקוח או פגישה לנציג

1. מנהל נכנס לפרופיל הלקוח ובוחר **נציג משויך**.
2. הנציג מקבל התראה **במערכת** (פעמון).
3. אם למי שמקצה יש WhatsApp מחובר, ולנציג יש **מספר נייד** בכרטיס המשתמש — נשלחת גם הודעת WhatsApp לנציג (לפי [`config/notifications.json`](config/notifications.json)).

### 3. מעקב יומי במסך סוכן

1. מסך **סוכן** (דף הבית).
2. לוח שבוע, מעקבים **להיום** ו־**באיחור**.
3. **מנהל מערכת בלבד:** סרגל «תצוגת מסך סוכן» — **שלי** / **הכל** / נציג ספציפי.  
   כשצופים כנציג אחר מופיע באנר «מנהל מערכת · צופה כ־…» (ההתחברות נשארת שלך — רק התצוגה משתנה).
4. בעלים ונציגים — רואים את המסך שלהם בלי בורר תצוגה.
5. צבעי מקור פנייה עוזרים לזהות מאיפה הגיע הליד.

### 4. מלאי — רכב, קטגוריות ותמונות

1. **מלאי רכבים** ← הוספה / עריכה.
2. בטאב פרטים: סמן **קטגוריות** (ריבוי בחירה) — למשל הייבריד + 7 מקומות.
3. במסך המלאי: סנן לפי קטגוריות (הרכב חייב לכלול את **כל** הנבחרים) + עמודת תגיות.
4. תמונות: גרור קבצים מהמחשב **או** תמונה מאתר אחר (גרירה/הדבקה מכתובת); נשמרות לדיוור WhatsApp.
5. ייבוא מלאי מ־Excel — רק מנהל.

### 5. בדיקת רכב להחלפה (טרייד־אין)

1. **בדיקת רכב להחלפה** ← מספר רישוי ← בדוק רכב (GOV + Autoboom + לוחות).
2. נתוני GOV מוצגים כשדות מסודרים (לא JSON גולמי).
3. מלא: ק״מ, יד, **מחירון**, **זיכוי ללקוח**, **תוספת מבוקשת**.
4. **תקציב יעד** = זיכוי + תוספת. המערכת מציגה עד 5 רכבים מהמלאי עם **תוספת נדרשת** והפרש (חסר/עודף).
5. «העתק למלאי חדש» מעביר נתונים (+ ק״מ/יד/מחירון) לטופס רכב חדש.

דוגמה: מחירון 140k, זיכוי 120k, רכב במלאי 135k → תוספת נדרשת 15k.

### 6. מחשבון מימון

1. מסך **מחשבון מימון** — חישוב ידני (ספיצר + בלון עד 40% ממחיר המחירון).
2. בדיוור רכב אפשר לסמן «מעוניין במימון» כדי לצרף שורת החזר משוערת להודעה.

### 7. דיוור ללקוח על רכב מהמלאי

1. מלאי ← פתיחת הרכב.
2. ודא חיבור WhatsApp במסך **WhatsApp / שליחה** (סריקת QR).
3. במודאל: בחירת לקוח / נייד, תמונות, הודעה.
4. אופציונלי: סמן **מעוניין במימון**.
5. שלח ב־WhatsApp.

### 8. חיבור WhatsApp לכל עובד

1. כל עובד נכנס עם המשתמש שלו.
2. **WhatsApp / שליחה** ← התחבר ל־WhatsApp.
3. סורקים את ה־QR **במסך** (הסשן רץ על השרת).
4. השליחות יוצאות מקו ה־WhatsApp של אותו עובד — אין צורך להתקין את הפרויקט במחשבי העובדים.
5. **תפוצה המונית** (קהל יעד) — למנהלים בלבד.

### 9. מכירה ומסמכים

1. **מכירות** ← עסקה חדשה (או ממודאל רכב: «צור עסקת מכירה»).
2. בפרטי העסקה: חוזה / אישור עסקה / קבלה לפי הצורך.
3. תפריט **הפקת מסמכים** (`#/documents`): בחירת סוג מסמך, מילוי פרטים, הפקת PDF פנימי.
4. הסכם רכב חדש: מספר הסכם עוקב; המערכת משלימה שדות סטנדרטיים.

### 10. קופה ודוחות

- **קופה:** רישום תשלומים.
- **דוחות:** סיכומים לפי סוג (דוחות רגישים — למנהלים).

### 11. הגדרת נייד לנציגים (להתראות WhatsApp)

1. מנהל → **ניהול משתמשים**.
2. עדכן מספר נייד לכל נציג שצריך לקבל הקצאות ב־WhatsApp.
3. ודא ש־`whatsapp.onAssignment` מופעל ב־`config/notifications.json`.

## קטגוריות רכב (סיכום)

רשימה קבועה — רכב יכול להיות בכמה במקביל:

| מזהה | תווית |
|------|--------|
| `electric` | חשמלי מלא |
| `hybrid` | הייבריד |
| `petrol` | בנזין |
| `diesel` | דיזל |
| `seats7` | 7 מקומות |

- על הרכב: `categories[]` (טופס רכב + פילטר מלאי).
- על הלקוח: `preferredCategories[]` (לקוח חדש + פרופיל) — סינון AND ואז דירוג תקציב/החזר.
- שדה «סוג מנוע» נשאר טקסט חופשי לתאימות; ההתאמה לפי הקטגוריות.

## פתרון תקלות מהיר

| בעיה | מה לבדוק |
|------|----------|
| `ERR_EMPTY_RESPONSE` ברשת | לפתוח **https** (לא http); לוודא ש־`RUN.bat` רץ |
| אין QR ב־WhatsApp | התחברות מחדש במסך WhatsApp; רענון דף |
| PDF לא נוצר | להתקין Chrome; לבדוק הודעת שגיאה (לעיתים נשמר גם HTML) |
| קטלוג יצרן ריק | סנכרון קטלוג GOV מממשק הניהול (מנהל) |
| התראת WhatsApp לנציג לא נשלחת | סשן WA של המקצה מחובר; יש נייד בכרטיס הנציג; `whatsapp.onAssignment: true` |
| פורט 3000 תפוס | `STOP.bat` או `npm run stop`, ואז `RUN.bat` שוב |
| אין בורר תצוגה במסך סוכן | רק `system_admin`; רענון קשיח / התחברות מחדש אחרי עדכון |
| נציג לא רואה לקוחות | ודא הקצאה / שהוא הקים אותם; מנהל מקצה בפרופיל |
| אין הצעות מלאי ללקוח | מלא קטגוריות ו/או תקציב/החזר; סמן קטגוריות גם על הרכב במלאי |
